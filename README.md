# Lab 01 — TCP Port Scan Investigation

## 1. Objective

Investigate TCP network traffic generated by a controlled Nmap scan from Kali Linux to an Ubuntu virtual machine using Wireshark.

## 2. Lab Environment

- Scanner: Kali Linux (`192.168.56.101`)
- Target: Ubuntu Linux (`192.168.56.102`)
- Network: VirtualBox host-only network (`192.168.56.0/24`)
- Tools: Nmap and Wireshark
- Packet capture: `lab01-nmap.scan.pcapng`

## 3. Scan Performed

The following command was executed from Kali Linux:

`nmap -sT -sV --top-ports 20 192.168.56.102`

This scan checked 20 common TCP ports on the Ubuntu virtual machine.

## 4. Evidence Observed

In Wireshark, the following display filter was used:

`tcp.flags.reset == 1`

The capture displayed TCP RST, ACK packets sent from Ubuntu (`192.168.56.102`) to Kali (`192.168.56.101`).

Examples of source ports observed included:

- TCP 22 — SSH
- TCP 80 — HTTP
- TCP 443 — HTTPS
- TCP 3306 — MySQL
- TCP 3389 — Remote Desktop

These are conventional service-port assignments. Their appearance in reset packets does not mean those services were running.

## 5. Analysis

The RST, ACK responses are consistent with TCP connection attempts reaching closed ports. The responses indicate that the connection attempts were reset rather than successfully established.

The scan was limited to 20 common TCP ports. It does not establish the state of all TCP ports, UDP services, or the overall security of the target machine.

## 6. Conclusion

This investigation demonstrated how Wireshark can be used to inspect TCP flags, source and destination addresses, and port numbers.

The observed reset responses provide evidence consistent with closed TCP ports on the Ubuntu virtual machine during the scan.
